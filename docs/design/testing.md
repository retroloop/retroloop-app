# Testing

> Citations of the form `retro N r-…` are this project's own retrospective
> records — the provenance of each rule. They live in the project's private
> process records; every rule is stated in full beside its citation, so the
> references are safe to ignore.

**Philosophy: "Test, not debug."** The AI proves behavior with reproducible tests; it never drives a browser by hand, never pokes state files, never fixes without a red test first.

## The core concept

**Every layer boundary is a typed contract. Test each layer against the contract below it, with the layer below replaced by a fake implementing the same imported type. Prove each real dependency's behavior once, in isolation. A handful of all-real scenarios prove only the wiring.**

- **Shape is locked by the compiler:** fakes implement types imported from the producer (`AppRouter`, `RecordRepository`). Producer changes → fakes and their tests fail to compile. Suites can't drift because they share a *type*, not code.
- **Behavior is locked by integration tests, once:** types don't say "a miss returns `undefined`" or "`BEGIN IMMEDIATE` serializes writers" — the real dependency is proven through its interface; after that every consumer may trust an honest fake.
- **Wiring is what's left:** composition roots, config, embedded assets, tailer→SSE. That's what the few all-real e2e scenarios exist for — few, because everything else is already proven cheaper one layer down.

**Always-on (the merge gate):** suites 1–6. Size caps: one contract suite per repository, plus read-model contract suites for use cases whose semantics must hold on both stores (first: `list-retros.contract.ts`, N4); one test per procedure happy-path + each typed error; one test per CLI command; every UI behavior in suite 4; **suite 5 capped at ~3 scenarios** (full loop · real-time two pages + CLI write · upgrade old DB → new binary). Runtime targets: 1–3+6 well under a minute; 4 in ~1–2 min; 5 in ~2 min; whole gate < 5 min. `retries: 0` — a flaky test is a bug in the test.

**On-demand only** (written when a ticket needs them): pure use-case unit tests; cross-process concurrency; WebKit runs (iPad parity — nightly or on report); visual regression `toHaveScreenshot`; install matrix on Windows/Linux (release tags); performance/large-ledger.

## R-MOCK-LOCK

> **R-MOCK-LOCK.** In `apps/web`, tRPC is mocked **only** by an implementation typed from `AppRouter` imported from `@retro/api`. There is exactly one mock module: `apps/web/test/trpc-mock.ts`. It must cover every procedure of the real router — no more, no fewer — with inputs/outputs typed as `inferRouterInputs<AppRouter>` / `inferRouterOutputs<AppRouter>`. No file under `apps/web` may define routes, handlers, fetch interceptors, response literals, or a second router. A PR that violates this is rejected regardless of whether tests pass.

Precedent: the dca247 "typecheck is the lie-check" decision record; this rule strengthens it after a past AI sneaked a custom router into a UI despite knowing the principle.

**Widening any tRPC output is necessarily a two-package change** (retro-11 `r-wire-widening-two-package`): every wire shape is a `z.strictObject` and the mock is `satisfies MockRouter`, so a new output field fails the web typecheck and the parity gate until the mock models it. "Additive only, don't touch `apps/web`" is an impossible pair — a wire widening is routed to the change that owns the typed mock, never split from it.

**Four ways the mock can lie, and who catches each** (retro-6 `r-mock-extra-field-blind`): a **missing** procedure, an **extra** procedure and a **mis-shaped** procedure are the compiler's, below; an **extra field canned into a procedure's answer** is not, and never was — TypeScript infers an arrow handler's return type from its literal and then checks the whole function type for assignability, so excess-property checking never fires on the answer. That fourth direction was the reviewer seat's alone — the most expensive detector the repo runs — until `scripts/check-mock-parity.ts` took it.

**Enforcement, three layers:**
1. **Compiler:** the mock is `satisfies MockRouter` (mapped type over the real router's procedure keys — missing, extra, or mis-shaped **procedures** fail to compile, and a field whose *type* is wrong fails with them); `web → api` is type-only (`verbatimModuleSyntax`, `useImportType`; `initTRPC`/router values unimportable).
2. **Gate scripts:** Biome `noRestrictedImports` bans `@trpc/server`, `initTRPC`, `msw`, `nock`, `node:http` in `apps/web`; `scripts/check-mock-lock.ts` fails on any second mock/link/handler definition; a procedure-set meta-test in `apps/api` asserts the mock's keys equal the real router's; and `scripts/check-mock-parity.ts` runs every mock procedure against the mock's own fixture world and validates each answer with the schema the real router validates it with — every shape in `views.schema.ts` is a `z.strictObject`, so an extra canned field fails the gate at any depth, including inside a list row and inside a streamed event's payload.
3. **Reviewer with veto:** a fresh-context `mock-lock-reviewer` agent on every change touching `apps/web/**`, `apps/api/src/trpc/**`, or `e2e/**`; binary PASS/FAIL with file:line evidence. Checklist: exactly one mock module? typed from `AppRouter`? any value import from api in web? any handler/fetch/route in web? any response literal not derived from `inferRouterOutputs`? any `.feature` step bypassing the tRPC client? **Plus the UI-minimalism check: what did this change add to the UI, and which requirement paid for it?**

**The pinned lists are FOUR, and adding a procedure or a use case moves all of them** (retro-7 `r-parity-plan-discipline`, corrected to four by retro-8 `r-pinned-lists-are-four`). The count is what a lane budgets by, so an enumeration that undercounts reads as complete while leaving a red test — which is exactly what happened when session 9's record-page lane added a use case and met a fourth list nothing had named:

1. **`apps/api/test/procedures.test.ts`** — the real router's procedure set, asserted as a named list rather than a count, so a newcomer fails by its own name. Two retro-4 removals (`requests.*`, `holds.*`) are asserted here by absence, and a procedure that came back would fail here too.
2. **`apps/web/test/procedure-set.spec.ts`** — the same set from the typed mock's side, computed from `AppRouter` as `ProcedurePath`. Between the two, the mock cannot quietly drift from the thing it stands in for.
3. **the `PLAN` in `scripts/check-mock-parity.ts`** — the list that has to actually *call* a procedure before any answer of it can be validated, and the one a lane forgets because presence failures are the other two's job.
4. **`packages/core/test/unit/app.test.ts`** — the App's whole use-case set, sorted and named. It fires on **use cases**, procedure-backed or not, so core work with no wire surface still trips it; it is the list the api/web/parity vantage could not see, and it failed exactly as designed.

**A plan step that reads a shape another step populates runs after that step.** The fixture world accumulates across the plan, so a listing taken before any mutation validates only the empty half of a null-until-populated shape, and an extra field canned into the populated half sails through. Proven in both directions with a planted field on `recordLifecycleSchema`: caught with the lifecycle write ordered first, silent with the listing first.

## Determinism

- **Fake `Clock` and `IdGen` ports** everywhere below e2e; `RETRO_TEST_CLOCK` env for spawned processes; seeded fixtures; serial Playwright projects for real-time scenarios and for the starvation class (`apps/web` §the `starved` project, and the stall-edge passage below for when a scenario belongs in it); temp stage (`--data`) + random port per run; `data-testid`-only selection in web tests.

## Operational rules

- **A bug is a failing scenario first,** at the lowest layer that can express it. The fix is done when that test passes and the rest stay green.
- **A race or flake lane opens with instrumentation, never with a fix** (retro-7 `r-relayed-diagnosis-unverified`): the first act is a trace that reproduces the mechanism, and the lane report shows the trace that convicts it. A diagnosis handed down from someone who did not instrument is a hypothesis, and session 8 relayed two of two wrong — the landing flake's "the page grows after the click" died on 25 traces whose `scrollHeight` never moved (the real cause was an unsettled smooth scroll racing the assertion band), and the keyboard flake's Radix focus-handoff theory died when the failure hit with focus already polled onto the tab (a single non-retrying `evaluateAll` racing React's commit; the right tab reads correct 5ms later). Either fix would have changed the wrong thing and left the flake alive under a claim of victory.
  **A settled-wait and the reading taken off it stay two separate calls** (retro-8 `r-rest-versus-fold-tension`): folding the reading into the same `page.evaluate` as the wait is better engineering — the page cannot move between the rest and the reading — and it silently disarms the scenario that certifies the wait. `expect.poll` accepts one long call however late it returns; its budget only bites *between* iterations, so a wait that concludes far too late stops being a failure and becomes a slow pass. Measured rather than reasoned: with the fold applied, the pre-fix wait the starved-renderer scenario exists to catch passed **10/10** (`c4ec0f7`, reverted by `e406ed8`; the commit trail and the measurement are in the s9-webfix lane report). So in `apps/web/features/steps/review.steps.ts` the `scrollAtRest(page)` call and the landing read that follows it sit inside the poll as two calls on purpose — a lock the poll can interrupt, not a refactor waiting to happen. **The two are mutually exclusive and the lock wins**; this is words only, deliberately, because the code is already right and what was missing is the reason at the place it constrains.
  **A measurement travels with its parallelism, or it is not reusable by anyone including its own author** (retro-13 `r-measurement-states-parallelism`): every rate or flake number states its **worker count and repeat form**; **"in isolation" MEANS `--workers=1`** and may not be claimed otherwise; **`--repeat-each N` under `fullyParallel` is N concurrent copies** — a load test, not a repetition, so a soak supplies its own contention; and two measurements are comparable only when their stated methods are. One flaky scenario was characterized five times in one night, each superseding the last — load-dependent, then ~40% "in isolation", then identical on both shells, then not the lane's — and settled only at the merge: 6/6 green at `--workers=1` and red only under parallel runs, on every branch including main, the serialized run spending **12.4s of the starved renderer's 15s budget**. Every earlier "isolated" number had measured a different condition under the same word. Instrumentation was never what failed — everyone instrumented, and `r-relayed-diagnosis-unverified` above held; what no rule governed was the VOCABULARY a number travels in.
  **A verdict travels with the machine it was taken on** (retro-15 `r-pause-protocol-cannot-quiet-machine`): every gate or suite result is recorded with **loadavg and swap at its moment** — the rule above widened from the run's own workers to the box they ran on, because a starved renderer burns no CPU and a machine can be busy in a way the run itself cannot see. **"Quiet" is a claim about the machine, and the lane pause protocol cannot manufacture it:** a hard pause every lane ACKed, with nothing of theirs running, still produced **four** timeout-shaped reds with browser-death signatures — the load was the gate's own five-worker chromium fleet at loadavg 42 on a box holding swap at **11.1 of 12.3 GB**, under ~20 long-lived sessions from other projects and 8 days of uptime that no lane protocol reaches; the lever's limit is stated where the lever is pulled (the process docs' quiet-tree gate passage). **And a substrate claim states its moment of measurement:** a swap reading of 0.00M taken at boot was reported as "the starvation substrate is gone" and corrected by a worker minutes later to 462M of a new 1024M swapfile — true when it was read, false when it was quoted, which is the entire content of the rule. The four-red spread (dashboard pending-count, records resolve-panel, portrait-iPad comments, landing-stall) is preserved with its signatures in the session evidence, and what became of it is the passage below — one of the four was the starvation class and the other three were the machine killing browsers, which is a difference the spread's own error text carries and nobody had read off it.
  **The stall edge is a scheduling boundary, not a budget, and it has its own Playwright project** (retro-13 `r-starvation-budget-vs-parallelism`, the owner's selected solution 2, landed session 13; it re-ratified and superseded retro-11 `r-menu-close-budget-stall-edge`'s budget moves). Four retros fixed this class at four layers — an unsettled wait, a re-scoped wait, a stall convicted under load, budget moves approved — and each fix was true where it stood. The shared trigger underneath all of them was **parallel contention against a wall-clock budget**: at the merge that closed it the landing scenario was 6/6 green at `--workers=1`, spending 12.4s of its 15s budget, and red only under the suite's own parallel workers, identically on every branch including main. Re-measured on the lane's own tip before anything moved: green at the gate's five workers (16.6s), and **12 of 12 red at twelve concurrent copies on twelve workers** — every one of them `Timeout 15000ms exceeded while waiting on the predicate`, the page alive in all twelve, at loadavg 103. A bigger number cannot fix that, because the number a starved renderer competes with is *however many browsers the suite happens to be running*. So the class leaves the parallel bulk instead: `apps/web/playwright.config.ts` carries a `starved` project selected by a `@starved` tag (`grep` against the bulk's `grepInvert`), and **it takes both halves** — `workers: 1` alone caps only that project's own concurrency while Playwright fills the remaining slots with the bulk's browsers, so `dependencies: ['chromium']` is what makes it *afterwards*. The same boundary `e2e/playwright.config.ts` has always drawn, for the same reason. Debug one without the other 330: `--project=starved --no-deps`.
  **When a scenario belongs in the serialized project**, all three, and the tag is the whole of the membership: it **starves its own renderer on purpose** — holds the main thread, throttles the CPU, makes frames seconds apart — rather than being slow, being flaky, or having died once under load; its claim is then **read against a wall-clock budget** that the starvation is meant to outlast, so the budget is the thing contention spends; and the class stays **small enough to serialize**, which today is two scenarios and by the record's own cost argument is never many more. **The counter-criterion is named because it is what the four-red spread got wrong:** a red whose signature is a *browser death* — `Target page, context or browser has been closed`, `Protocol error … session closed`, a locator answering `undefined` — is not in this class however timeout-shaped it looks. That is the machine killing a browser under memory pressure, not a renderer overrunning a budget, and the three candidates that carried those signatures (dashboard pending-count, records resolve-panel, portrait-iPad comments) deliberately did **not** move. Serializing them would treat a memory casualty as a scheduling problem, and a criterion loose enough to admit them admits the whole suite.
  **What the boundary does not buy, said where a merger will read it.** A dependency project that fails takes its dependents with it as skips, so under a red bulk the serialized project reports that it did not run — which is not a pass and must never be counted as one. And serializing removes the contention this suite creates, not the contention the box is under: the machine rule above still applies, unchanged.
  **A wait against a starved renderer is certified by its budget, and the harness cannot certify more than that** (measured in the same lane, `.git/…/retro-plant.log`). Two limits worth knowing before writing another scenario in this class. Playwright's `click()` does not return until the page has reacted to it, so a defect that lets a step return early is invisible: with the app menu's close-wait deleted outright the close was over at t=2040ms and the first reading that could be taken landed at t=2181ms, and the scenario stayed green. And the two starvation engines are not interchangeable — holding the page's main thread *quantises* it into whole periods and lets a close commit entirely inside one, between two of the harness's acts, so budgets are never spent and a plant against them is inert; Chromium's CPU throttle scales the work instead, so budgets are spent and a budget sized for a healthy page is red. The certification that survives both is the honest one: `chrome.feature` §the app menu opens, closes and arrives drives the whole menu walk at ×50 and is red with every budget in it cut to 300ms — 10 green → 10 red → 10 green, one worker.
  **The verification standard, revisited at #18's landing and rewritten** (retro-15 `r-two-part-verification-standard`, whose own expiry clause said *"when #18's serialization project lands, this passage is revisited by name"* — it landed in session 13 and this is that revisit). Invented ad hoc mid-session, the interim form verified four merges in one night and prevented both failure modes it exists for: no blind retry-until-green ever ran, and no false red blocked a healthy merge. What #18 changed is the **first** condition, and it changed it in the only direction the evidence allowed. The interim rule waived a red that was *"timeout/starvation-shaped AND in the convicted class"* — but the class it named now runs in a project of its own, so a starvation red cannot appear in the parallel bulk unless a scenario has joined the class without carrying the tag, and **the answer to that is the tag, not a waiver**. Meanwhile three of the four reds the interim rule was applied to were never that class at all: they were browsers being killed on a box holding swap at 11.1 of 12.3 GB. The waiver was doing real work; it was just doing it for a different reason than the one written on it.
  So the standard keeps its shape and states what it actually meant. **A gate red is waivable for merge purposes only when ALL of these hold:**
  1. **The red is the machine's, evidenced at its own moment** — a browser-death signature (`Target page, context or browser has been closed`, `Protocol error … session closed`, a locator answering `undefined`) recorded together with the loadavg and swap that produced it. "Timeout-shaped" was never sufficient and is not a category on its own.
  2. **It is not in the serialized project.** A red there ran on one worker after every other test in the suite had finished, with nothing of this suite beside it — there is no contention left to attribute it to, so it is a failure and it blocks. The same is true of the project reporting that it *did not run*: a dependency failure skips it, and a skip is not a pass.
  3. **The diff is argued, and where possible verified, reader-free of the failing surface.**
  4. **One serialized whole-suite run is green.**
  5. **Both runs are pasted with their worker counts** (the vocabulary rule above — "serialized" MEANS `--workers=1`), **and no retry is silent**: every re-run is stated, with what changed between them.
  Anything short of all five is a red that blocks, and the standard is the merger's to apply, never the lane's to claim. **The counter-example is still the shape test's proof:** a 0-second typecheck failure (`Cannot find module 'recharts'` — install-state lag, retro-15 `r-install-state-drift`, now healed at the gate) also produces a gate red, and the standard **refused** to waive it, because a 0-second FAIL is nothing's contention and no serialized green can make it one. That refusal is what distinguishes a standard from an excuse. **And this waiver has no successor expiry, because it is no longer about a test property.** What remains waivable is a machine fact that no lane protocol reaches (`r-pause-protocol-cannot-quiet-machine` above); the occasions for it end when the box stops swapping, not when a record lands.
- **Every NEW browser scenario is soaked in its own lane before merge** (retro-7 `r-new-scenario-soak`): run the new scenarios at `--repeat-each` of at least 10 — session 8's evidence bar was 15 — and put the count and the result in the lane report. One green run is the merge bar and a 1-in-7 race passes it about 86% of the time, so two races shipped inside one session-7 merge and billed every session after it: multi-run gates, false suspicion of innocent lanes, and `retries: 0` — a principle the owner can see — turned into a coin flip. Both fixes were trivial once diagnosed; the whole cost was in the escape. Scoped to new scenarios because soaking the suite on every merge is unaffordable and the marginal risk lives in what has never been repeat-run.
- **Plant-and-catch is a standing rule** (retro-1 `r-falsifiability-paid`, owner-approved): every worker plants representative defects and watches its own suites catch them before reporting; the report names the plants and what caught each. A check never observed failing is an unverified claim — this practice found two real bugs that every written test had passed.
  **Plant through `scripts/plant.sh`, which is the safe order rather than a reminder of it** (retro-6 `r-plant-revert-second`): `scripts/plant.sh --check <check-cmd> [--expect-green] <file>… -- <apply-cmd>` refuses to run while any of its targets carries uncommitted work, and `scripts/plant.sh --revert` reverse-applies exactly the diff it planted — never a checkout, tree-wide or per-file, so work written into the file after the plant is not the plant and does not go with it. If the plant's own lines were edited under it the revert fails loudly and changes nothing, rather than guessing which half to keep.
  **The cycle is enforced, not described: green baseline → plant → red → revert → green** (retro-7 `r-ineffective-plant-blind`): `--check <check-cmd>` names the command whose red certifies the plant, deliberately separate from the apply command that lays it, and the harness runs it three times — before the plant, which must be **green** or there is no baseline a catch could be attributed to; with the plant applied, which must be **red** or the plant is inert and is rolled back rather than certified; and after `--revert`, which must be green again or the cycle certifies nothing. `--expect-green` is the single exception, for an absence assertion that legitimately stays green, and it is logged as an acknowledgement rather than as a catch. Session 8 filed a plant that edited a tally but not the `useMemo` dependencies that recomputed it: the diff was non-empty, the suite stayed green at 214/214, and the report was about to read "the scenario failed to catch it" — a non-empty diff was never evidence of anything, and only one worker's judgment stood between that plant and a lane report. **All three results are logged as generated fact**, refusals included, in `$(git rev-parse --absolute-git-dir)/retro-plant.log`; read it with `scripts/plant.sh --log`. A report's plant table is copied from there rather than recollected, and the check's own full untruncated summary lines travel beside it.
  **A number quoted as a reading is PASTED from that log, never typed** (retro-13 `r-invented-evidence-reads-real`): a certified cycle and a finished control now END by printing that run's log block already formatted to paste — the green/red/green verdicts with the log's path above them — so the honest form is what the terminal already holds and inventing one costs *more* effort than copying it, which is where keystroke-level rules win and warnings lose (the `card.sh` precedent). Any reading quoted anywhere a reader will trust it — a lane report, a test comment, a docstring — cites the path of the log that produced it, beside it; a reading with no citable log is written as **expected**, never as observed. The instance is why the tool moved rather than the prose: a lane committed a doc comment asserting a control run that never happened, with invented numbers — "16 against a menu bottom of 56" where the real cycle read **18 against 57** — wrong on both figures and by too little to look wrong, repaired across three commits (fa0b66c claimed, 0f197c9 retracted, 4a6defd earned) plus a merge-time JOURNAL correction, and the author had this very rule in hand when writing it. Invented evidence does not look invented, and a number reads as measured *by being* a number.
  **The prose it replaces is why it exists** (retro-4 `r-plant-revert-hazard`): reverting a plant must never be able to take the fix with it — and **twice in three sessions it did.** Session 5 lane B: the worker finished a fix, its scenario, and a fixture change — all uncommitted — then planted a defect and reverted it with a tree-wide `git checkout -- .`; the revert erased all three along with the plant, and all three had to be rewritten. Session 7: a worker ran `git checkout -- SKILL.md` before committing six cold-gate fixes and erased every one of them, having quoted this very rule in an earlier report of its own. That is the shape of the failure — a habit asked for at the one moment attention is on the plant table rather than on git state — and it is why the rule is now a script. The order it enforces is the order that was always right, and the only part still left to a person is the first step: **commit the fix**, then plant, and the harness runs the cycle above.
  **A control is declared, never improvised** (retro-7 `r-control-test-signature`): reproducing something against another tree's content — `git checkout main -- apps/web`, restored one command later — is byte-identical in git signature to the work-destroying revert above, so a read-only reviewer found one mid-lane, read it as the `r-plant-revert-second` shape, and session 8 paid an emergency interrupt and a full evidence re-take over a legitimate control. Intent cannot be observed, so it is declared: `scripts/plant.sh control --why "<what you are reproducing>" [--from <rev>] <file>… -- <cmd>` refuses a dirty target set on the same standard as a plant, snapshots the lane's files, writes the other tree's content **without ever touching the index** — `git show`, never `git checkout`, so the staged wholesale revert is a signature the mode cannot produce — runs the command, and restores the lane unconditionally, on success, on failure and on interrupt. The declaration is written to the log **before the command starts**, because an observer who can only read it afterwards is reading an explanation rather than a declaration. Two worker habits ride along as the rule the mode implements: **never revert your own lane files for evidence** — a control borrows content, it does not undo work — and **print `git status --porcelain` beside every number**, so the tree state is on the record next to the result it produced.
  **After ANY content restore — plant revert, control, checkout — rebuild before serving, and verify the bundle carries your change** (retro-13 `r-stale-dist-after-control`): a restore puts *source* back and rebuilds nothing, so `apps/web/dist` goes on serving the bundle built before it. This is the mirror of the merge-side rule already written down — a web-only merge needs only the rebuild, *since the build is served from disk per request* (retro-3 `r-stale-server-verify`, the process docs' verification-before-relay rule) — one fact read from opposite sides, of which only the merge side had ever been stated where the serving step reads it. The verification is a grep of the **built** assets for a marker only your change emits, not a re-reading of the source. All three session-11 bake-off lanes walked into this and one caught it exactly that way; the cost of missing it was the owner reviewing main's shell as a lane's variation. Every restore path in `scripts/plant.sh` prints the warning at the moment the trap arms, because three lanes had read the doc and one grep is what saved the day.
  **When a plant fails to fail, suspect the test data before the assertion** (retro-5 `r-assertion-value-distinctiveness`): a fixture must be representative enough to exercise the behavior under test — a terse mock `why` puts no flex-shrink pressure on a label-width assertion — and an expected value must be distinctive enough that its presence implies correctness, which a `toContain` check cannot claim against a document that quotes wrong values as counterexamples.
  **A check is designed against its nearest alternative** (retro-13 `r-checks-without-discrimination`): before writing it, name what else would also pass it. **A fixture varies ONLY the axis the assertion keys on** — a fixture where every entity differs on every axis identifies no axis; **a claimed rate states its sample size** and cannot come from a handful of runs; **a visual result is verified by probing the property at the moment of capture, never by looking at the output.** Four instances in one session, all under the rules above: a fixture keyed every session to its own directory, so six passing tests could not tell grouping-by-session from grouping-by-cwd — on the real store (nine sessions, one checkout) that undetected difference collapses the whole diary into one card; a test named a NaN guard and proved nothing about it, because without the guard the comparator fell through to a tie-break producing the same order at the fixture's ids, and the fix was a discriminating fixture (id 99 — fallback puts it first, the guard puts it last) rather than a weaker test; a 5/5-green sample was read as "deterministic" against a believed ~40% rate; and two visual inspections passed screenshots carrying a real artefact, where only a probe at shutter time (`boxShadow: 2.18px` — a transition mid-flight) discriminated — *"my own verified fix was incomplete, and looking could not tell me."* The rule above governs what a fixture RETURNS; this one governs which axes it varies.
- **Position, scroll, and focus assertions are shown to fail** (retro-3 `r-uncontrolled-assertions`): every new assertion about position, scroll, focus, or anything the browser partially does on its own is hand-run with the behavior deleted — per assertion, not per lane — and the lane report records that run's failure output. The browser doing half the job for free is exactly how a toothless assertion ships green. Deleting your own lane's behavior to prove an assertion is a **plant**, so it goes through `scripts/plant.sh --check` like any other; `control` mode borrows *another tree's* content, which is a different thing under a similar name.
- **Themed visual states are asserted in both themes, and style signatures per channel** (retro-5 `r-theme-blind-assertions`): any assertion about a visual state a theme can change runs in light *and* dark, driven through the app's own toggle — a selected-verdict styling that the outline variant's dark overrides suppressed shipped green because the scenario only ever rendered one theme. And a style-signature assertion compares each style channel on its own, never as one joined value: any single surviving channel satisfies a whole-string inequality, so the joined form passes a broken state and cannot name which property carried the difference.
- **OS-acting seams default to no-op in the harness** (retro-3 `r-os-seam-harness-default`): any runtime seam that touches the OS — kill, spawn, network, filesystem outside the stage — is a no-op under test by default, injectable to *enable*, never to disable. A seam that defaults live once nearly killed the test runner.
- **The mock world is stateful and typed, and both properties are load-bearing** (retro-3 `r-mock-world-semantics`): a module reload resets the world — never `page.reload()` after a MockControl call; and a field the world does not model must not be canned — model it or leave it to fail the type check. The mock module's own header carries the same two sentences.
- **Suite 5 runs under Node, not Bun** — Playwright spawns its own runtime, so no Bun APIs (`Bun.*`, `bun:sqlite`, `import.meta.dir`) in `e2e/`; Bun-specific work goes through helpers spawned as real Bun processes (retro-1 `r-e2e-runtime-node`).
- **No manual browser driving, ever.** The AI looks at the UI only through Playwright screenshots/traces. "Just checking something" = write a scenario.
- **No ad-hoc state probes** — diagnostics go through `retro doctor` and structured logs.
- **Never truncate a runner's summary** (retro-7 `r-shell-filtered-verdicts`): a positional filter over a suite's output can crop exactly the line that carries the verdict, and twice in one session one did. Extract counts only with a failure-preserving pattern — `grep -E "[0-9]+ (passed|failed|flaky)"` — and **every count in a report travels with its full summary line beside it**. A `| tail -1` that kept "29 passed" and dropped "7 failed" was about to report a live keyboard flake as not reproducible, the exact opposite of the truth; every number taken through a cropping filter had to be re-measured before it reached a report.
- **Never suppress bddgen's output, and a passing web run proves nothing unless bddgen regenerated in the same command** (retro-7 `r-bddgen-stale-green`): generation failure *is* the output, so muting it converts a failed regeneration into a silent stale-green. `bddgen >/dev/null 2>&1 && playwright test` reported 3 passed off the previous generation, because a typographic apostrophe in a step name against the feature's straight one made bddgen report "Missing step definitions" into `/dev/null` — exactly the class of difference a human eye skips.
- **Verification before relay:** the orchestrator never forwards an agent's "done". Standing check (used on the dashboard mocks, kept as a script): headless-load every route with **zero console errors and zero pageerrors**, non-empty bodies, no byte-identical screenshots, clean worktree, claimed artifacts actually present.
